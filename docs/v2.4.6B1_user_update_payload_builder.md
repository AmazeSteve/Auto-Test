# v2.4.6B1 — Safe User Update Payload Builder

## 范围与最终行为

Builder 仅使用 Python 标准库，由 Read Model 确定性生成 27 字段白名单
baseline，再 deepcopy 并覆盖唯一支持的 `usr_display_bil`，重新计算实际
changed_fields。输入、baseline、mutation 相互隔离。没有 HTTP、ApiClient、
Context、Effect、Lifecycle、YAML 或 restore/request runtime 依赖。

本次补充只完成 B1。工作区保留上一轮授权的 A1 `actual - allowed` 修复及
三个回归场景；本轮没有进一步修改任何 core 文件或 destructive YAML。

对照完整 RFC 后补齐：

- `usr_gender` 仅接受 `M`、`F`、`""`，拒绝 null 和其他值。
- `roleCode` 拒绝空 token 和重复 token；用 strip 后的 token 检测空白及
  等价重复，但不改写或重新排序已接受的角色字符串。
- 三个可空关系 ID 保留 null；非 null 必须为非空 ID。空串/空白拒绝，
  包括 RFC 倾向拒绝的 `subordinateDepartmentId=""`，不做静默规范化。
- 13 个普通可空资料字段保留 null 与空串之间的区别。

`usr_ent_id` 的真实样本类型是正整数 `1830`。正 ASCII 数字字符串是明确的
兼容策略，由 `test_valid_raw_user_entity_ids_preserve_original_type[compat-decimal-string]`
验证；并未声称服务器响应本身使用字符串。两种类型均不强制转换。

空 mutable set 加空 overrides 允许生成两份独立相等的载荷，符合用户指定的
subset / key equality / actual diff equality 规则。它不触发任何写请求。
