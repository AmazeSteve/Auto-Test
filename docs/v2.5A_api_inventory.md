# v2.5A API Inventory & Coverage Analyzer

This independent tool reads local Java mappings, Postman evidence, Endpoint YAML
and raw Case YAML. It produces static inventory and case-design recommendations.
It never executes requests, resolves credentials, starts or compiles WizBank,
uses a database, generates endpoints/cases, or imports the framework runtime.
`CASE_COVERED` means an enabled YAML case exists; it makes no execution claim.

## Run

```bash
python scripts/api_inventory.py \
  --source /path/to/wizbank.zip \
  --postman /path/to/postman.zip \
  --repo-root . \
  --output-dir .runtime/api_inventory
```

Both inputs also accept directories. Paths are caller supplied; no uploaded
asset locations are embedded in production code. ZIPs, including nested Postman
ZIPs, are read in memory without extraction. Unsafe/duplicate normalized member
names and escaping directory symlinks fail. No Postman scripts or variables are
evaluated. Fatal input/configuration/report errors return 2 without quoting
parser exceptions; unresolved ordinary evidence is retained in reports.

The default output is the Git-ignored `.runtime/api_inventory/`. A custom output
cannot overlap `data`, `core`, `services`, `utils`, `.git`, or an input directory.
Report files use atomic replacement, so existing report-name symlinks or hard
links cannot redirect writes into production assets. Input ZIPs remain external
analysis assets and must not be committed.

## Frozen identity and path policy

Identity contains `service`, uppercase `method`, `route_fingerprint`, sorted and
deduplicated `params`, `headers`, `consumes`, `produces` mapping conditions, and
sorted dispatch signature. The UID is the complete SHA-256 of UTF-8 JSON with
sorted keys, compact separators, Unicode preserved and non-finite numbers
forbidden. Endpoint IDs and ordinary parameter values never identify APIs.

HTTP(S) authorities, queries and fragments are removed. HTTP scheme comparison
is case insensitive; protocol-relative URLs are treated as URLs. Repeated path
slashes and trailing slashes normalize centrally. For service `wizbank`, `/app`
is removed only at a complete prefix boundary; the runtime path is also kept.
`{name}`, `{{name}}`, `${name}` normalize to `{}`. Concrete numbers, UUIDs and
strings remain concrete. No other deployment prefix is guessed.

Spring conditions retain operators and ordinary literals. Comparisons on
credential-like keys project their literal values to full SHA-256 digests;
presence-only conditions retain their names. Raw values are hashed exactly once
at the identity boundary, including values which happen to look like digests.
Unresolved source evidence uses the same safe projection before reporting.

## Source candidates

The parser lexes comments, strings, character literals and text blocks before
recognizing annotations and declarations. It balances delimiters, parses literal
Spring attributes, composes class and method paths (Cartesian arrays), and expands
RequestMethod arrays. Standard Spring annotations and RequestMethod constants
require an exact FQN, explicit Spring import, or the corresponding unambiguous
Spring package wildcard import. Bare simple names are not proof. Visible
same-package/local declarations, foreign explicit imports, and competing
wildcard imports prevent inferred Spring semantics. Fully qualified references
remain independent of simple-name shadows. Java's implicit java.lang import
supports Deprecated when no visible declaration/import shadows it; full Java
symbol solving and static imports remain unsupported. Reports include file
counts for Spring imports and unresolved mapping provenance. Class and
method method restrictions use Spring union semantics; params/headers combine,
and method consumes/produces replace nonempty class defaults.

Methodless mappings remain `ANY`/`AMBIGUOUS_METHOD`. Literal REST controllers,
ResponseBody and clearly HTTP ResponseEntity/HttpEntity returns provide HTTP
classification. Clear view returns provide PAGE_ROUTE; other controllers remain
UNKNOWN_ROUTE. Deprecated/internal evidence is kept. Non-controller mappings
do not establish active HTTP exposure.

ResponseEntity, HttpEntity, ModelAndView, View and RedirectView return types use
the same conservative provenance resolver: exact FQN, explicit exact import,
or the corresponding unambiguous package wildcard. Bare or shadowed simple
names provide no HTTP/view proof. String uses java.lang implicit import when no
visible local, same-package or explicit-import shadow exists; only literal
String returns establish a view. Fully qualified return types remain independent
of simple-name shadows, including class/method type variables. Generic
`ResponseEntity<byte[]>` remains supported when its base type is proven.
The return-only wildcard policy does not relax annotation/RequestMethod rules.

Constants/concatenation, inherited mapping semantics, custom/meta annotations,
SpEL and unsupported route patterns, Java symbol/bean registration and arbitrary
execution are not resolved. Unsupported files receive safe parse notices;
partial records from failed files are discarded. Scanner limitations are also
included in report metadata. The supplied Java archive uses both `java/` and
`src/main/java/` layouts; this is not a Maven-module or backend compilation tool.

## Postman and legacy evidence

Supported inputs include the supplied `$kind: http-request` YAML export and
standard Postman Collection JSON. Query/header fields may be dictionaries or
key/value lists; JSON/form-data/urlencoded bodies provide safe key names.
Environment/global documents, auth values, cookies, raw bodies and ordinary query
values are omitted. Structured query metadata is authoritative for duplicate raw
query keys, including disabled fields. Empty URLs become `POSTMAN_EMPTY_URL`.

Nested ZIP copies are removed only when matching member paths across packaging
boundaries have identical bytes. Distinct duplicate requests remain evidence
lists and duplicate-report entries; environment files never resolve variables.

Known logical identities are qdbAction (`cmd`), Dispatcher (`module` + `cmd`)
and aeAction (`cmd`, proven by the supplied handler). Only literal dispatch
identifiers from servlet query/form parameters are retained. Missing/conflicting
or templated dispatch values are `LEGACY_UNRESOLVED`; ordinary page/date fields
and JSON body values do not become dispatch identities. Handler logic alone
does not prove deployed business exposure. The analyzer did not establish
servlet deployment exposure from the supported scanned evidence, so its logical
legacy operations default to UNRESOLVED. It does not parse web.xml deployment semantics.

## Reconciliation and eligibility

Matching uses exact canonical identity first, then a unique source template with
the same service, method, mapping conditions, dispatch signature, segment count
and fixed segments. Multiple templates become `AMBIGUOUS_DYNAMIC_MATCH`.
Whole-segment dynamic matching is conservative; partial-segment placeholders
are not inferred from concrete strings. Fuzzy names never authorize a match.
Evidence arrays and all outputs sort deterministically. Source declaration
collisions and canonical Registry/Postman duplicates are reported without
deletion, guessed resolution or changing runtime assets.

Eligibility is ELIGIBLE, EXCLUDED or UNRESOLVED. Resolved, active, nondeprecated,
noninternal HTTP source evidence without identity collisions is eligible.
Reliable PAGE_ROUTE/deprecated/internal evidence is excluded even when its HTTP
method is ambiguous. Postman-only REST and unproven legacy exposure remain
unresolved. Conflicting source classification remains unresolved. Static case
coverage follows effective Case identity after frozen shallow field overrides
and special header/tag merge semantics; disabled cases never cover an API.

Metrics use unique canonical UID sets:

- Registration Coverage: eligible APIs with valid Registry definitions / eligible APIs.
- Static Case Coverage: eligible APIs with resolved enabled cases / eligible APIs.
- Registry Utilization: registered APIs with resolved enabled cases / registered APIs.

Zero denominators yield null and `NOT_APPLICABLE`. Raw evidence counts are
reported separately, including disabled cases, empty URLs and packaging copies.
The frozen framework has 13 definitions, 22 enabled and 2 disabled raw cases;
all 13 registered canonical APIs have enabled cases (100% utilization).

## Explicit analyzer-only overrides

```yaml
apis:
  <full-64-character-api-uid>:
    eligibility: EXCLUDED
    business_risk: 20
    module_weight: 50
```

Pass `--overrides /path/to/overrides.yaml`. Keys are full existing canonical UIDs;
unknown APIs/fields, invalid enum/boolean values, and non-finite/out-of-range
scores fail. Allowed fields: `eligibility`, `api_kind`, `active`, `deprecated`,
`internal`, `resolution_status: RESOLVED`, `active_business_exposure`, `readonly`,
`business_risk`, `module_weight`. Applied fields appear on each API and in
metadata. A methodless ANY identity cannot be guessed into a concrete method.
Overrides never become runtime dependencies or execution authorization.

## Priority and reports

The queue exposes coverage_gap, evidence_confidence, business_risk, change_risk,
automation_feasibility, module_weight, total and safety_gate. Unconfigured
business risk remains 0/UNCONFIGURED; URL words do not imply business risk.
Eligible Source+Postman readonly gaps rank ahead of uncertain evidence.
GET/HEAD/OPTIONS are static readonly candidates; actual business semantics still
require review. Clearly mutating Java operation declarations (for example
`delExamine`, `updateUser`, `saveRecord`) add a conservative `mutation_candidate`
flag even for GET; this uses declaration names, never URL-word business-risk
inference. The flag does not change identity or eligibility and cannot be
bypassed by a readonly override. This naming check can miss writes and can flag
methods needing semantic review; it grants no execution permission.
Mutation/destructive candidates without a complete static
recovery contract are BLOCKED_FOR_IMPLEMENTATION. Static lifecycle structure
does not establish successful restoration. All gates require review and grant
no execution permission.

Seven deterministic UTF-8 artifacts are produced without timestamps:
`api_inventory.json`, `api_inventory.csv`, `coverage_summary.json`,
`unresolved.csv`, `duplicates.csv`, `api_inventory_report.md`,
`priority_queue.csv`. JSON retains safe evidence arrays, explicit overrides and
scanner limitations. Markdown contains Summary, Coverage, Coverage Gap, Legacy,
Excluded, Unresolved, Duplicates, Priority Queue and Scanner Limitations. CSV/JSON
contain complete data when Markdown limits displayed rows. Actual counts follow
these rules and input contents; RFC estimates are not targets.


Analyzer tests cover synthetic credentials across Authorization, Cookie, bearer,
query/body/password/client-secret fields, complete reports/stdout, directory/ZIP
equivalence, determinism, conservative denominator rules, frozen merge semantics
and report link safety. Existing frozen runtime regression/collection gates
remain independent of inventory results.
