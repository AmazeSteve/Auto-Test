# v2.5B-4 runtime bootstrap

This version is offline only. It keeps the existing runtime, authentication,
workflow groups, lifecycle, and functional-test serial policy.

## Repository evidence

The baseline contains a UTF-16 `requirements.txt` with 79 pinned distributions.
It already declares the critical runtime and pytest dependencies. No dependency
installation or requirement change is needed for this slice. No tracked lockfile,
`pyproject.toml`, or GitHub Actions workflow was found.

`YamlUtil.load_all()` has an inverted existence check, but no framework caller
uses it. Registry loading uses `read_as_list()` and `load()`, so `load_all()` is
recorded here and remains unchanged.

## Endpoint registry

`EndpointRegistry` remains a process singleton:

- Construction with the same canonical source reuses its valid snapshot.
- An explicit different source loads a new snapshot before publishing it.
- `load(source)` explicitly reloads even the current source.
- A failed scan, read, parse, or validation preserves the last snapshot and source.
- The no-argument form requires a previously initialized, valid snapshot.
- An explicitly supplied empty directory is a known, valid empty snapshot.
- YAML paths are sorted by their relative POSIX representation. Directory scans
  propagate errors and do not recurse into symlink directories.
- `get()` returns a deep copy; callers cannot mutate nested cached values.

`source_dir` exposes the canonical source as a read-only property. No registry
dependency is passed through runners, and no production reset helper is added.

## Config startup

`Config(env)` validates the environment identifier before opening a file. Empty,
traversal, and separator-bearing identifiers fail. YAML must be a mapping.

`base_urls`, `request`, and `default_headers`, when supplied, must be mappings.
Host keys and URL values must be nonempty strings; URLs need an HTTP(S) scheme
and host. HTTP remains supported. Timeout must be a positive number, excluding
booleans. An explicit `verify_ssl` must be boolean.

Missing sections retain their prior defaults: empty mappings, timeout `30`, and
`verify_ssl=False`. Startup neither coerces values nor inspects unused credentials
or passwords. Host-bound credential lookup and the Host-be legacy fallback remain
unchanged. Header values receive no new type restriction.

Startup errors use safe categories. The public failure boundaries also hide
private configuration/path arguments from default pytest traceback output.

## Environment manifest

From the checkout root:

```bash
python scripts/runtime_manifest.py --execution-mode unit
```

The script also works from another working directory when invoked by its path.
It bootstraps imports from its own location, including checkout paths containing
Unicode or spaces. It does not start tests or make HTTP requests.

Schema version `1` contains:

| Field | Meaning |
| --- | --- |
| `schema_version` | Integer schema version |
| `python` | Implementation and version |
| `platform` | OS system and machine architecture |
| `versions` | Installed versions of eleven named critical distributions |
| `dependency_digests` | Raw-byte SHA-256 by fixed logical dependency filename |
| `git_sha` | Full local 40/64-hex SHA, or `null` |
| `execution_mode` | Optional caller-supplied safe metadata label |

The version list includes pytest, xdist, Allure, dependency/order/rerun/timeout
plugins, requests, PyYAML, jsonpath-ng, and Faker. Missing distributions are
explicit `null` values. The digest allowlist covers `requirements.txt`,
`requirements-dev.txt`, `constraints.txt`, `pyproject.toml`, and common lockfiles.
Files are hashed as bytes, including the baseline UTF-16 requirements file.

Modes are `offline`, `unit`, `unit-xdist`, and `functional-collection`. They record
intent only and grant no execution permission. There is no timestamp, environment
dump, Config content, credential material, home directory, or absolute project
path in the manifest.

Success and help exit `0`; invalid arguments exit `2`; manifest construction
failure exits `1`. CLI errors do not echo supplied arguments or private payloads.
An unavailable Git command/repository gives a `null` SHA. A present but unreadable
dependency asset fails safely instead of disappearing from the manifest.

This is an observation of the installed environment, not a new lockfile or an
automatic dependency installer. It does not claim general functional xdist
support or backend readiness. Controlled Validation is not required for this
offline scope.
